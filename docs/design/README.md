## 设计决定

- 根仓库统一维护合同、文档和跨服务联调；工具实现、测试与工具依赖集中于 `tools/`，根目录通过 `./dev` 调用；`frontend/`（Nuxt 公开站、Vue 管理端）与 `backend/`（Go API）是独立 Git 子模块，各自构建、提交和发布。根提交固定双方提交组合，一个私有内容仓库另用于同步 Markdown 和图片。
- 公开页面由前端 Node 服务渲染；Go 提供唯一业务 API，独占 SQLite、资源、认证与 Git 工作区。
- 四类内容统一采用稳定对象与不可变版本；文章、项目、资料和技能分别有类型字段。草稿不会改动公开标题、分类、封面或路由。
- 同步任务与网站内容事务提交，Git 在事务外执行。冲突解决先核对远端，再应用用户明确指定的动作。
- 管理写操作统一采用会话、CSRF、幂等键和业务版本校验；公开访客不能提交站主身份字段。

## 开发顺序

2026-11-17 已将执行顺序细化为[开发计划 P0–P7](../development-plan.md)，目录及代理协作遵循 [AGENTS.md](../../AGENTS.md)，阶段完成遵循[本地联调规范](../local-integration.md)。

1. P0 先落地代码规范、目录、中文注释和子代理协作规则，已完成。
2. P1 三个独立工程、本地 HTTPS、真实数据库与认证已完成；P2 接着实现内容发布闭环。
3. P3 用临时真实 Git 仓库验证文章往返、冲突和崩溃恢复。
4. P4–P6 完成四类内容、公开与管理页面、图片、分类、评论和完整同步；边界明确的模块可交给子代理并行开发。
5. P7 对整合版本进行本地全量联调、独立构建替换、备份恢复与性能基准，再按实际环境准备部署验收。

2026-11-17 已完成 P1 工程与认证，三端独立构建、真实 HTTPS 及浏览器验证通过，见 [P1 本地说明](../development/p1-local.md)与[验证记录](../verification/P1-2026-11-17.md)。生产服务尚未部署。2026-11-23 已配置根仓库及前后端子模块的 GitHub 地址，本轮不推送，远程 CI 仍需在推送后执行；域名、托管商和运行预算继续保留为部署输入。

## 文档优先级

需求基线定义产品行为；本详细设计细化执行方式。接口路径与字段以 OpenAPI 为准，数据库约束以迁移文件为准，事务与跨表不变量以数据库设计为准。修改任一合同须同步关联文档和验证样例。早期方案中的表名、路径缩写和类型命名由本版具体定义替代。
