# 个人网站需求文档

版本：1.3 需求基线  
更新日期：2026-11-15  
状态：核心功能规则已完成评审，技术与接口已形成详细设计，部署容量及上线实测参数待补齐  
适用范围：首版产品、交互设计、技术方案及验收

建设一个用于长期记录与分享的公开个人空间，技术与生活内容并重。首版覆盖个人介绍、项目经历、技术能力、技术博客、生活分享、文章评论和留言板，并支持后台与代码仓库自动双向同步。

第 2 节记录用户已确认的决定，其余章节将这些决定展开为可实施、可验收的规则。第 14 节记录评审结果，并将未单独确认的常规设计默认项与用户已确认规则分开标注；具体技术及部署参数见第 13 节。

## 1 目标与建设原则

- 建立持续积累技术文章和生活记录的个人内容空间。
- 让首次访问者了解站主、浏览代表项目和相关技术能力，让读者发现、阅读、分享文章并参与交流。
- 后台与本地文件都可以维护内容，避免重复录入。
- 技术与生活在导航和首页均有清晰入口，优先保证阅读、导航和维护体验。
- 首版完成核心流程，再扩展功能；整体风格简洁温暖。
- 技术方案偏向轻量、便于部署和维护，不采用 Java；采用前后端分离，前端通过 API 访问后端，支持独立构建与部署。具体框架与托管平台在技术方案中细化。

## 3 用户角色与权限

| 角色 | 可以执行的操作 | 边界 |
| --- | --- | --- |
| 普通访客 | 浏览已发布内容、搜索文章、提交评论和留言、回复其他访客、查看公开回复 | 不需要账号，不访问草稿或管理数据，不能自行编辑或删除已提交内容 |
| 站主 | 维护资料、项目、文章及分类标签，管理图片，回复和管理互动，处理同步问题 | 通过已认证的管理身份操作 |
| 同步服务 | 在指定仓库范围内读写内容，处理同步事件与状态 | 只处理约定内容，不导出互动数据或账号凭据 |

首版按单站主维护设计，不建设访客账号体系和多作者权限体系。站主标识根据认证身份生成，访客填写相同昵称不能获得该标识。

## 4 页面结构与浏览流程

下列路径为设计参考，技术方案可以调整，但应保持公开链接稳定。

| 页面 | 参考路径 | 主要内容与操作 |
| --- | --- | --- |
| 首页 | `/` | 简短个人介绍、技术和生活入口、两类最新文章、精选项目入口 |
| 关于我 | `/about` | 个人简介、技术能力、公开联系与社交链接 |
| 项目列表 | `/projects` | 项目封面或占位图、名称、简介、技术标签、详情入口 |
| 项目详情 | `/projects/{slug}` | 项目背景、个人职责、实现方案、成果、图片和可选外部链接 |
| 技术博客 | `/blog` | 技术文章列表、分类和标签筛选、搜索入口 |
| 生活分享 | `/life` | 生活图文列表、分类和标签筛选、搜索入口 |
| 文章详情 | `/posts/{slug}` | 标题、摘要、时间、正文、分类标签、目录、评论 |
| 搜索结果 | `/search` | 关键字、内容类型筛选、文章结果和无结果提示 |
| 留言板 | `/guestbook` | 留言说明、提交表单、公开留言和回复 |
| 管理后台 | `/admin` | 内容管理、互动管理、同步任务与站点配置 |

公开主导航为六个入口，搜索通过图标或输入框进入。管理后台不占用公开主导航位置。文章详情路径独立于技术或生活分类，调整内容类型时保持链接不变。

主要流程：

1. 首次访问：首页了解站主 → 进入技术、生活或项目 → 阅读详情 → 查看关于我或参与互动。
2. 查找内容：进入列表或搜索 → 输入关键字或选择分类标签 → 查看结果 → 阅读文章。
3. 参与交流：在评论区或留言板填写内容 → 提交 → 查看立即公开的内容及回复。
4. 后台维护：编辑并保存草稿或修改稿 → 预览 → 明确发布 → 通过本地校验后网站生效 → 异步同步仓库。
5. 仓库维护：本地修改并标明版本用途和公开状态 → 推送指定分支 → 网站接收并校验 → 无冲突时更新修改稿或公开版本。

## 5 首版功能需求

### F01 首页

- 展示头像或个人形象、显示名称、短介绍，以及关于我入口。
- 技术与生活均展示最新内容，两个区域具有相近的视觉层级。
- 展示站主选择的代表项目，进入独立项目详情页。
- 不显示草稿、已撤回内容或空白卡片；某类尚无内容时提供自然的空状态。

### F02 个人资料与技术能力

- 维护头像、显示名称、短介绍、详细介绍和公开联系链接。
- 所在地、职业描述、邮箱、社交链接等均由站主选择是否公开，不要求填写真实姓名或电话。
- 技术能力按领域或技能组组织，展示名称、实践说明及相关项目或文章。
- 默认通过文字和实践案例表达能力，不要求技能百分比。
- 个人资料与技术能力均支持后台编辑和仓库同步；登录资料与公开个人资料分别管理。

### F03 项目经历

- 提供项目列表和独立详情页，支持草稿、发布、未发布修改稿、回收站及自定义展示顺序。
- 详情支持名称、简介、封面、背景或目标、个人职责、技术方案、成果、图片及可选链接。
- 可选链接包括源码、演示站点或相关资料；没有链接时不显示无效按钮。
- 项目可以关联技术能力及相关文章。
- 首版项目不附带独立评论区，访客可通过留言板交流。

### F04 技术博客与生活分享

- 两类内容共享文章能力，分别提供列表入口。
- 文章包含标题、摘要、正文、内容类型、分类标签、可选封面、发布与更新时间。
- 列表默认按首次发布时间倒序分页；修改旧文章不自动改变首次发布时间。
- 正文支持 Markdown 常用结构：标题、段落、链接、列表、引用、表格、图片和代码块。
- 根据正文二级、三级标题生成目录；无相应标题时隐藏目录。
- 代码块支持语法展示及一键复制，复制结果有明确提示。
- 生活内容采用正文内多图形式；首版不提供独立相册和短动态模块。
- 文章预览与公开页面采用一致的正文渲染规则。
- 已发布文章可单独保存修改稿，未明确发布前不改变线上版本；修改稿支持后台与仓库同步。

### F05 分类与标签

- 一篇文章归属一个内容类型，可选择一个分类，并关联多个标签。
- 分类区分技术与生活，标签可跨类型使用。
- 站主可以新增、改名或删除分类标签。删除已被引用的分类标签前，应允许迁移或移除关联，不删除文章本身。
- 列表支持分类、标签筛选，展示当前条件并允许清除。
- 仓库写入的分类标签按统一标识或名称映射，避免双端产生重复记录。

### F06 文章搜索

- 搜索技术和生活文章的标题与摘要，不检索正文。
- 只返回已发布文章，不返回草稿、已撤回文章或非公开字段。
- 支持按全部、技术、生活筛选；结果显示标题、摘要、类型、时间和详情链接。
- 默认按发布时间倒序显示匹配结果；匹配时忽略首尾空格及英文字母大小写。
- 空查询显示输入引导；无匹配结果时保留关键字，并提供清除条件的入口。
- 搜索结果随公开内容更新或撤回而一致变化。

### F07 文章评论与留言板

- 均无需注册，昵称和正文必填，邮箱可选且不公开。
- 提交成功后立即公开；未通过字段校验、重复提交检查或限频的内容不作为成功提交。
- 评论关联文章，留言独立于文章；只有已发布文章可以接受新评论。
- 访客可以回复其他访客，首版采用根评论及平铺回复，显示所回复的昵称，不形成无限层级。仅可回复当前公开的内容，父内容隐藏或删除后拒绝新回复。
- 站主回复具有明确标识，普通访客昵称不构成身份认证。
- 站主可按来源查看、回复、隐藏、恢复和删除内容；隐藏内容不出现在公开页面及公开计数中。
- 隐藏根评论时连同回复一起隐藏，恢复时保留各回复原有的单独隐藏状态；删除根评论时一并删除回复，操作前显示影响范围。
- 文章撤回后，评论保留供站主管理并停止公开；重新发布时恢复其中未被隐藏或删除的评论。
- 访客首版不能自行编辑或删除已提交内容，也不提供邮件回复通知。
- 昵称建议为 1–40 个字符，正文为 1–2000 个字符，去除首尾空白；邮箱填写后须符合基本格式。
- 访客正文按纯文本展示，不执行 HTML、脚本或嵌入内容。
- 提交失败保留已填写内容，重复请求不生成多条记录。限频参数在上线验收前确定。
- 邮箱不出现在公开页面、公开接口、搜索结果或内容仓库中，仅站主按管理需要查看。

### F08 管理后台

- 提供站主登录、退出和会话失效处理；实现见[站主登录与会话](development/owner-session.md)。
- 维护个人资料、技术能力、项目、文章、分类标签和图片。
- 支持 Markdown 输入及预览，首版不要求独立的富文本编辑器。
- 提供保存草稿或修改稿、发布、更新发布、撤回、移入回收站、恢复和彻底删除流程，明确显示当前操作对线上内容的影响。
- 展示评论与留言来源、正文、时间和管理操作。
- 展示同步状态、最近成功时间、失败原因及处理入口；可重试失败任务和解决冲突。
- 配置站点名称、介绍和仓库连接参数；敏感连接参数不写入内容仓库。

### F09 图片与资源

- 后台支持上传文章图片、头像和项目图片；本地 Markdown 支持引用随内容维护的图片文件。
- 后台上传的内容图片纳入可同步资源，本地拉取后能够继续编辑和预览。
- 内容及必需图片在网站本地准备完成后再生效；向仓库传输可异步执行。仓库导入时，也需先将必需图片准备完成，避免正文已发布而图片尚未可用。
- 保留原始图片，公开页面可以使用优化版本；优化不改变正文引用含义。
- 图片支持说明文字并保持比例，大图不撑破正文或手机屏幕。
- 仅用于草稿或修改稿、尚未公开过的图片不通过公开接口或可猜测路径提供访问；同一图片被已发布内容引用时可以公开。已公开资源的撤回按当前站内引用处理。
- 删除图片前检查引用，仍在使用的图片需先替换或解除引用。
- 首版不提供评论附件上传；格式、单文件限制和存储方式在技术设计中确定。

## 6 内容模型与字段

下表定义业务信息，不限定数据库结构。所有可同步内容需要稳定标识和版本信息；接口区分公开字段与管理字段。

| 对象 | 必需信息 | 可选信息 | 同步范围 |
| --- | --- | --- | --- |
| 个人资料 | 稳定标识、显示名称、短介绍、公开状态 | 头像、详细介绍、所在地、职业、公开链接 | 展示资料参与；登录信息不参与 |
| 技术能力 | 稳定标识、名称、领域、实践说明、排序、公开状态 | 关联项目、关联文章 | 参与 |
| 项目 | 稳定标识、访问标识、名称、简介、版本正文、发布状态、排序 | 未发布修改稿、时间范围、技术标签、封面、链接、关联内容 | 正常内容及修改稿参与；回收站保留网站恢复数据 |
| 文章 | 稳定标识、访问标识、标题、摘要、类型、版本正文、发布状态 | 未发布修改稿、分类、标签、封面、首次发布时间 | 正常内容及修改稿参与；回收站保留网站恢复数据 |
| 分类与标签 | 稳定标识或唯一名称、分类所属类型 | 展示顺序 | 随内容关系同步 |
| 图片资源 | 稳定资源路径、类型、大小、内容版本 | 说明文字、尺寸、优化版本 | 原始资源参与 |
| 评论与留言 | 标识、来源、所属文章或父留言、昵称、正文、时间、可见状态 | 私密邮箱、站主身份标识 | 不参与 |
| 同步记录 | 对象标识、方向、基础版本、目标版本、状态、时间 | 错误摘要、冲突关联 | 仅供管理 |

后台创建内容时自动生成稳定标识；本地新增内容可由内容模板提供标识，或在首次同步时生成并回写文件。已有文件丢失标识时不得直接当作新内容重复导入。重复标识、访问标识冲突、缺失其他必需字段及无法解析的内容，进入校验失败状态，不覆盖现有公开内容。更名、移动文件或修改类型时保留稳定标识及互动关联。

同一内容对象可以同时拥有一个当前公开版本和一个未发布修改稿。两者共享对象标识，但具有不同的版本标识和用途；发布内容、未发布修改、回收站状态及同步进度分别记录。已发布内容的字段校验作用于拟发布版本，保存不完整修改稿不要求其立即满足全部发布条件。

## 7 发布状态与编辑规则

### 7.1 发布状态

| 状态或操作 | 公开表现 | 管理行为 |
| --- | --- | --- |
| 未发布草稿 | 内容不公开 | 可编辑、预览、同步，校验通过后可发布 |
| 已发布且无修改稿 | 当前公开版本可以访问 | 新建修改稿不改变线上版本 |
| 已发布且有修改稿 | 继续展示原公开版本 | 保存和同步修改稿不触发发布，站主可预览、继续编辑或发布 |
| 发布或更新发布 | 本地校验及资源准备成功后生效 | 初次发布记录时间，更新保留首次发布时间；随后异步同步仓库 |
| 撤回 | 立即停止网站公开，不等待仓库 | 保留公开过的版本、现有修改稿和评论，记录撤回变更并同步 |
| 移入回收站 | 立即停止网站公开，不等待仓库 | 保留内容版本、修改稿、资源引用及评论，供恢复 |
| 恢复 | 恢复为未发布状态，不自动重新上线 | 保留稳定标识、原链接和评论关联，由站主再次点击发布才公开 |
| 彻底删除 | 内容不能再由站内回收站恢复 | 单独展示影响并确认，清理站内内容及关联评论；共享图片不级联删除 |

后台未保存输入不触发同步。“保存修改稿”只保存并同步未发布版本；“发布”或“更新发布”才将选定版本对外生效。预览不影响线上内容。已有修改稿时再次保存不覆盖当前公开版本；发布成功后将该修改稿标记为已应用。

仓库文件协议区分对象的公开状态、当前公开版本和未发布修改稿。推送修改稿只更新编辑内容；明确更新公开版本才自动发布；明确撤回对象才使其停止公开。不能用同一个草稿标记同时表达“保存修改”和“撤回线上内容”。首次发布未指定时间时使用实际生效时间，后续修改保留该值；首版不实现定时发布。

关于我作为固定入口存在，个人资料和技术能力分别遵循发布与同步规则；未发布的模块不显示，页面提供适当空状态。

### 7.2 保存与生效

后台分别展示修改是否保存、线上生效版本及仓库同步进度。正常发布通过网站本地校验、图片准备和持久化后即可生效，不等待仓库；同步失败显示“已发布，仓库同步失败”，不能误报为发布失败或自动撤销已生效版本。

撤回和移入回收站立即停止网站访问、列表展示、搜索返回及新评论提交，再异步更新仓库。仓库离线、同步冲突或重试中的旧任务不能自行重新公开这些内容。同步状态至少包含待同步、同步中、已同步、失败和冲突，独立于草稿、已发布和回收站状态。

### 7.3 回收站与恢复

文章或项目进入回收站时，保留全部站内版本和现有评论的各自可见状态，暂停公开访问及新评论。回收站资源继续计入引用保护，不能作为未使用图片直接清理。仓库中的正常内容文件会随删除变更移除，恢复数据由网站备份覆盖。

恢复后保持未发布状态，保留最后公开版本和修改稿供选择，由站主再次点击发布后才公开。恢复后的内容同步到仓库时仍保持未发布，原有评论在重新发布前也不公开。回收站首版不自动过期清理。彻底删除应明确列出内容及评论影响，执行前需要确认；这不等同于清除 Git 历史或已有备份。恢复后继续使用原稳定标识和链接，若链接已被占用则提示处理，不能静默覆盖其他内容。

## 8 自动双向同步

### 8.1 范围与文件约定

- 首版连接一个私有内容仓库、一条指定分支和一个约定内容目录。
- 文章和项目正文采用 Markdown；标题、稳定标识、状态、分类标签等写入结构化元数据。
- 个人资料和技术能力采用可读的结构化文件或带元数据的 Markdown，具体格式由技术方案统一定义。
- 文件协议必须能同时保存已发布版本和未发布修改稿，标明各自用途。内容版本与对象身份分离，禁止把同一对象的两种合法版本误判为重复内容。
- 同步覆盖个人资料、技术能力、项目、技术与生活文章及其内容图片。
- 评论、留言、访客邮箱、登录资料、密钥、运行日志和管理配置不进入内容仓库。
- 未识别字段和不支持语法必须保留或明确拒绝该变更，不得在往返转换时静默丢弃。
- 草稿与修改稿不在网站公开，但保存在私有同步仓库中。仓库连接范围与提供方在技术方案中确定。

### 8.2 后台到仓库

1. 站主保存修改稿、发布或撤回，系统按操作类型执行校验并持久化变更。
2. 保存修改稿保持线上不变；发布通过本地校验后更新线上；撤回或移入回收站立即下线。同时可靠地记录待同步任务。
3. 任务携带对象及基础版本信息，比较仓库最新版本；存在双端修改时进入冲突流程。
4. 无冲突时更新相应内容、修改稿与资源，成功后记录共同版本和同步状态。
5. 同步失败保留任务与已生效网站版本，允许重试；重试不得覆盖其后发生的撤回、删除或新版本。

### 8.3 仓库到后台

1. 指定分支发生变化后，自动接收更新事件或按约定机制拉取变更。
2. 校验格式、对象及版本标识、引用、公开状态和资源完整性，区分公开版本与修改稿。
3. 与后台自最近共同版本起的变更比较，无冲突时更新对应版本及共同版本。
4. 修改稿只更新编辑内容；公开版本变更自动发布；撤回状态停止公开。确认对象被删除时移入回收站。发生冲突时先保留网站当前状态，不自动应用对端修改。
5. 编辑页能提示内容已被仓库更新；未保存输入不能被无提示替换。

### 8.4 冲突规则

- 同一内容在两端相对于最近共同版本都发生修改时标记冲突，包括修改与删除、修改与撤回相遇的情况；首版不自动合并不同字段，不以时间较新者自动覆盖。
- 两端最终内容相同不视为冲突，不同对象的独立修改可以分别处理。
- 冲突时保留双方修改和网站当前公开或下线状态，展示基础版本、后台版本、仓库版本及差异。网站可能已发布新版本，不能自动回退到最近共同版本。
- 支持选择后台版本、选择仓库版本，或手动编辑合并结果。
- 解决前重新检查两端版本；如果出现新变化，刷新比较，不能用过期结果覆盖新内容。
- 解决时明确展示结果是只保存修改稿、发布选定版本、撤回还是移入回收站；选择一个版本本身不能暗中触发发布。确认结果后按正常操作在网站生效，并异步同步仓库。

### 8.5 失败与删除规则

| 情况 | 处理要求 |
| --- | --- |
| 网络中断或仓库暂不可用 | 保留修改和任务，维持网站当前已生效状态，提供有限自动重试和手动重试 |
| 凭据失效或权限不足 | 停止无效重试，提示修复连接，不回显密钥 |
| 格式或字段无效 | 指出对象和字段，保持该对象的上一个有效版本 |
| 同一事件重复到达 | 幂等处理，不创建重复内容，不重置首次发布时间 |
| 同步写入引发新事件 | 识别自身同步版本，避免无限往返提交 |
| 事件乱序或编辑页过期 | 对照版本处理，不允许旧版本静默覆盖新版本 |
| 网站发布所需图片缺失 | 本次发布不生效，保留修改稿和上一公开版本；仅向仓库上传失败不撤销网站已生效版本 |
| 仅修改路径或标题 | 通过稳定标识识别原对象，保留链接及互动关联 |
| 仓库移除文章或项目对象文件 | 无双端冲突时自动移入回收站并下线；有冲突时保留网站当前状态，交站主解决 |
| 后台移入回收站 | 立即下线并保留恢复数据，异步同步仓库删除；失败不使网站内容重新公开 |
| 只移除修改稿文件或资源文件 | 不解释为删除整篇内容，按丢弃修改稿或资源引用校验处理 |
| 彻底删除后收到旧事件 | 保留必要的删除版本记录，旧任务或旧事件不得自动复活内容 |

删除判断基于同一次仓库变更中的完整对象关系和稳定标识，不能只凭旧路径消失判定。文章或项目从仓库删除只进入回收站，不直接彻底删除。独立对象允许分别成功，具有引用依赖的内容与资源必须在网站准备完整后再生效。

## 9 视觉与交互要求

- 采用简洁温暖的个人博客风格，颜色、字体和图形由视觉设计确定。
- 通过排版、文字和适量图片体现个性，主要信息不依赖复杂动效才能获取。
- 手机与桌面均支持完整阅读和互动，手机导航可折叠，正文保持舒适阅读宽度。
- 正文与代码的字号、行高和对比度便于阅读；长代码和宽表格在自身区域滚动。
- 页面提供加载、空内容、无结果、提交中、成功和失败反馈。
- 表单错误关联具体字段，失败后保留已填写内容。
- 主要操作可通过键盘完成，具有可见焦点；图片可填写说明文字，按钮名称明确。
- 首版使用一种默认主题，不要求主题切换、多语言或复杂动画。

## 10 质量与运营要求

### 10.1 内容与访问边界

公开接口只读取当前公开版本和明确公开的字段，不能混入修改稿中的标题、摘要、图片或分类标签。未认证访客不能访问管理操作、私密邮箱、草稿、预览地址和同步详情。正文与访客输入采用明确的渲染边界，不执行未经允许的脚本内容。

### 10.2 搜索引擎与链接

公开页面具有独立标题、描述和稳定链接。生成已发布页面的站点地图，管理页面不参与收录。摘要及分享信息随当前公开版本更新。修改访问标识时保留旧链接的跳转关系；撤回后旧链接不可继续暴露正文。

### 10.3 性能与同步时效

列表分页，正文图片按需加载并预留尺寸；长代码和多图文章不阻塞导航及表单操作。缓存更新不能继续暴露已撤回内容。

服务器、访问规模和网络条件尚未确定，本版不承诺具体响应时间、并发量或同步时限。技术设计需明确测试环境、内容规模、页面性能目标和正常同步完成时限，并据此执行上线验收。

### 10.4 备份与恢复

备份范围包括内容、原始图片、互动数据及必要配置。内容仓库不能替代评论、留言和运行数据备份。上线前完成一次恢复演练，验证文章、图片及互动关系；备份周期、保存时长和恢复目标在部署方案中明确。

### 10.5 运维可见性

站主能够查看发布结果、同步失败和基本服务异常。日志应便于定位问题，避免记录明文凭据和不必要的访客个人信息。监控与通知渠道随部署方案确定，首版不强制引入访问分析平台。

## 12 首版之外

首版明确不包含独立相册、短动态、全文搜索、RSS 订阅、访客账号、多作者权限、独立富文本编辑器、定时发布、邮件通知、项目独立评论区以及访客自行编辑删除已提交内容的功能。

点赞收藏、多语言、主题切换及访问统计仪表盘按当前设计默认留到后续，不作为首版验收要求。后续增加上述任一功能时，需同步更新需求范围与验收标准。

站主希望先上线核心内容，再逐步完善。任务依赖和交付安排统一由[开发计划](development-plan.md)维护。
