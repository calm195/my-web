# 个人网站页面原型设计

版本：1.1  
日期：2026-11-15  
依据：[需求文档 v1.3](personal-website-requirements.md)与[轻量技术方案 v1.2](personal-website-technical-design.md)

## 1 设计定位

原型采用简洁温暖的个人博客方向，技术与生活并重。临时站名为“一隅”，用于建立完整的视觉语境，不代表站主已经选定品牌。所有文章、个人经历、项目、昵称和统计均是示例。

公开页面以阅读为中心：首页介绍、技术与生活入口、最新内容、代表项目。管理端以任务为中心：编辑、发布、处理同步、管理互动。原型控制条独立于网站导航，提供浏览网站、内容管理、说明和重置入口；正式网站不保留这条评审工具栏。

本轮原型使用 HTML、CSS 与原生 JavaScript，零构建依赖；这便于快速评审布局和状态。正式实现采用前后端分离：公开网站由 Nuxt 负责页面与渲染，管理端由 Vue 3 / Vite 负责交互，二者通过 Go API 访问数据，并分别构建和部署。原型浏览器状态只用于演示。

### 1.1 前后端分离后的交互衔接

- 公开页面数据与管理数据使用不同 API。正文和目录来自后端统一 Markdown 管线；前端负责排版、锚点、代码复制及交互。
- 进入管理端先检查会话；失效时显示登录入口。保存遇到会话失效或网络失败时保留当前输入供重新提交，不静默丢弃。
- 编辑冲突依据后端 409 响应展示对比，不能仅依赖浏览器保存的版本判断。发布成功和仓库同步状态仍分开显示。
- 正式站点访问页面数据时提供加载、重试和服务暂不可用状态，接口失败不显示成“没有文章”。

以上是正式实现的接口交互约定；在线静态原型尚未演示真实登录、网络请求或 API 错误。现有页面结构与视觉稿可继续用于评审。

## 2 视觉规范

| 项目 | 设计值与用途 |
| --- | --- |
| 页面底色 | 暖白 `#f6f4ee`，降低长篇阅读的视觉压力 |
| 卡片与编辑面板 | 微暖白 `#fffdf8` |
| 正文主色 | 深灰绿 `#293d38` |
| 主操作 | 深绿 `#38594d`，用于发布、提交等主要动作 |
| 点缀色 | 陶土色 `#ae5f43`，用于强调、生活内容细节 |
| 分割线 | 灰绿 `#dedfd4`，弱化容器边界 |
| 标题 | 系统宋体或衬线字体，首页桌面约 52 px、手机约 39 px |
| 正文 | 系统无衬线字体，文章约 16 px，行高接近 1.95 |
| 代码 | 系统等宽字体，独立深色背景，支持局部横向滚动 |
| 容器 | 桌面最大约 1120 px，手机保留两侧阅读边距 |
| 圆角 | 面板约 8–16 px，主视觉使用拱形轮廓 |
| 图像 | 本项目绘制的山间、窗边与代码主题 SVG 示意插画 |

主要操作有文字标签、键盘焦点与状态反馈；减少动画，并遵循系统减少动态效果的偏好。字体使用系统回退，原型不依赖外部字体服务。

## 3 页面结构

原型采用 `#/` 路由，静态托管无需服务器路由配置；正式站点使用需求文档中的正常路径。

| 页面 | 原型入口 | 内容与交互 |
| --- | --- | --- |
| 首页 | `#/` | 个人空间介绍、技术列表、生活图文、精选项目 |
| 关于我 | `#/about` | 个人介绍、技术能力、关联项目与联系入口 |
| 项目列表 | `#/projects` | 项目名称、简介、技术标签和独立详情 |
| 项目详情 | `#/projects/project-garden` | 项目背景、职责、方案与成果示例，不设独立评论 |
| 技术博客 | `#/blog` | 分类与标签筛选、文章卡片、搜索入口 |
| 生活分享 | `#/life` | 图文卡片、分类与标签，与技术内容区分 |
| 文章详情 | `#/posts/small-architecture` | 摘要、正文、目录、代码复制、评论与平铺回复 |
| 搜索 | `#/search` | 仅搜索公开文章的标题与摘要，内容类型筛选、空状态 |
| 留言板 | `#/guestbook` | 昵称、可选邮箱、正文、提交结果与回复 |
| 后台概览 | `#/admin` | 内容数量、待处理同步、最近内容和留言 |
| 内容管理 | `#/admin/content` | 文章、项目、个人资料和能力统一列表 |
| 编辑器 | `#/admin/edit/git-notes` | Markdown、预览、修改稿、发布、独立同步状态 |
| 同步中心 | `#/admin/sync` | 失败重试、冲突入口、模拟离线和仓库删除 |
| 冲突处理 | `#/admin/conflict/git-notes` | 三方版本比较、编辑合并结果、明确应用方式 |
| 评论管理 | `#/admin/comments` | 来源筛选、站主回复、隐藏、恢复与删除 |
| 图片资源 | `#/admin/media` | 原图与引用数量示例，上传存储待正式实现 |
| 回收站 | `#/admin/trash` | 恢复为未发布、单独彻底删除 |
| 设置 | `#/admin/settings` | 基本信息与仓库配置的只读布局示意 |

## 4 关键交互

### 4.1 编辑与发布

编辑器主区为标题、摘要和正文，右侧为内容类型、分类标签、封面及状态。在手机上，状态和设置改为上方信息区，正文保持足够宽度。

“保存修改稿”保留尚未发布的内容，公开页面读取原公开快照。“更新发布”明确切换公开快照，并单独显示仓库同步情况。离开时存在未保存输入会提示处理，预览不等于发布。

原型不实现完整 Markdown 扩展集，只演示标题、段落、列表、引用、图片、链接和代码。正式版表格、代码高亮、清洗与预览一致性由统一后端渲染实现。

### 4.2 同步与冲突

线上状态与同步状态分别呈现。网站可以“已发布，同时仓库同步失败”，不把两者合为一个成功或失败状态。

冲突页并列展示共同版本、网站端与仓库端；窄屏纵向排列。摘要直接比较，正文可以展开，合并结果可编辑。默认仅保存修改稿；发布、撤回、移入回收站均须在应用方式中明确选择。

同步中心的“模拟仓库离线”“模拟双端修改”“模拟仓库删除”仅用于原型评审，正式产品不保留这些模拟按钮。

### 4.3 评论与留言

访客无需登录。提交后立即显示，邮箱不出现在公开评论中；回复放在所属根留言下，标明回复目标，站主回复显示标识。

后台隐藏根留言时，前台整组不显示；恢复后尊重回复自己的隐藏状态。内容移入回收站后停止公开，恢复内容仍保持未发布，评论随再次发布恢复可见。

原型中的站主身份由评审入口模拟，没有真实权限隔离。浏览器存储可被同一浏览器检查，不能用于保存真实私密邮箱或凭据。

### 4.4 图片与空状态

首页和列表使用有明确尺寸的插画，避免加载时大幅跳动。项目无外部链接时不生成无效按钮。搜索无匹配、无文章、无评论、无同步问题和回收站为空时，均给出具体说明。

## 5 原型评审路径

1. 从首页分别进入技术和生活内容，比较两者的视觉层级。
2. 在技术博客选择分类或标签，进入搜索查找“周末”。
3. 在留言板用示例昵称提交，再用另一昵称回复。
4. 打开内容管理，编辑一篇已发布文章，保存修改稿，再查看线上版本。
5. 在同步中心模拟仓库离线，回到编辑器发布，检查“已发布 / 同步失败”。
6. 打开初始的同步冲突，编辑合并结果，保持“仅保存为修改稿”并应用。
7. 删除一篇文章，进入回收站恢复，确认它没有自动重新公开。
8. 使用底部“重置”恢复初始示例。

## 6 本轮验证记录

验证日期：2026-11-15。使用 Codex 内置浏览器访问本地原型，语法检查使用 `node --check`。以下均指原型行为，不代表真实后端验收。

| 检查 | 观察结果 |
| --- | --- |
| JavaScript 语法 | 通过 |
| 分类与标签 | 修正了同名分类与标签混用的问题；分类“工程实践”只返回该分类的 1 篇文章 |
| 标题摘要搜索 | 搜索“周末”返回 1 篇匹配生活文章 |
| 匿名留言与平铺回复 | 示例留言立即显示，另一访客可回复并标明目标 |
| Markdown 预览 | 可切换正文输入与渲染预览；修正了 hidden 属性被显示样式覆盖的问题 |
| 修改稿隔离 | 保存修改稿后，公开标题保持原版本；未发布标题不出现在文章详情 |
| 模拟仓库离线发布 | 页面显示已发布，同时独立显示同步失败 |
| 回收站恢复 | 恢复后详情显示暂未公开，等待再次发布 |
| 人工冲突处理 | 默认保存修改稿，公开摘要保持原版 |
| 响应式布局 | 首页 360、768、1440 px 宽度及编辑器 360、1440 px 宽度检查未出现整页横向溢出 |
| 控制台 | 已检查的操作中未观察到脚本错误日志 |

本轮未实施或验收：真实登录与权限、Git 网络读写及崩溃恢复、持久服务端数据、真实上传与图片访问控制、备份恢复、并发和性能、跨浏览器及真机兼容。永久删除按钮具有原型流程，但本轮浏览器检查未执行该不可恢复分支。

原型样例数据在验收后已重置；上线静态包不含浏览器验收过程中输入的数据。
